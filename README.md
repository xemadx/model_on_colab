## ۱. معرفی پروژه

سرویس‌های ابری رایگان و اشتراکی مثل **Google Colab** پردازنده‌های گرافیکی قدرتمندی نظیر **NVIDIA L4 (24GB VRAM)** و **NVIDIA T4 (16GB VRAM)** در اختیار توسعه‌دهندگان قرار می‌دهند. با این حال، اجرای مدل‌های زبانی عظیم ۲۷ میلیاردی با کانتکست‌های بزرگ (>16K) روی این محیط‌ها با موانع جدی زیر روبروست:

1. **محدودیت سهمیه و قطع ناگهانی (Preemption & Idle Reaper):** کولب نشست‌های بدون وب‌سوکت فعال فرانت‌اند را پس از ۳۰ دقیقه خاموش می‌کند و اجرای دو GPU همزمان روی یک حساب را مجاز نمی‌داند.
2. **کمبود حافظه و سرریز VRAM:** مدل‌های ۲۷B در فرمت FP16 حدود ۵۴ گیگابایت حافظه می‌خواهند و حتی با کوانتیزاسیون Q5_K (۱۹.۵ گیگابایت)، اضافه شدن کش کانتکست بزرگ باعث OOM کرش می‌شود.
3. **مشکلات ارتباطی و فیلترینگ:** نیاز به پورت‌فورواردینگ بدون نیاز به IP ثابت یا ثبت دامنه.
4. **به‌هم‌ریختگی ظاهری متون دوزبانه:** نمایش برعکس کدها و پرانتزها و قرارگیری نامتعارف اسکرول‌بار در سمت چپ در زبان‌های راست‌به‌چپ (RTL).

پروژه **`model_on_colab`** راهکار معماری و کد نهایی و بهینه‌سازی‌شده برای حل یکپارچه تمامی این چالش‌هاست.

## ۳. تجربیات فنی و حل چالش‌های کلیدی

### ۳.۱ ریشه‌یابی خطای HTTP 530 و مکانیزم انقضای کولب

حین توسعه و تست مدل، با خطای ناگهانی زیر در کنسول مرورگر مواجه شدیم:
```text
/api/chats:1 Failed to load resource: the server responded with a status of 530 ()
Cloudflare Tunnel error: Error 1033
```

#### ریشه‌یابی دقیق:
1. **قانون ۱ ران‌تایم GPU برای هر اکانت کولب:** گوگل اجازه نگه‌داشتن همزمان بیش از یک ماشین GPU را به یک کاربر نمی‌دهد. وقتی ماشین جدیدی ساخته می‌شود در حالی که نشست قبلی زنده است، کنترل‌پلین گوگل پس از حدود ۳۰ دقیقه ران‌تایم دوم را با وضعیت `session_terminated: pruned` حذف می‌کند.
2. **مکانیزم Idle Reaper:** اگر کدی با `nohup` در پس‌زمینه اجرا شده و اتصال SSH یا نوت‌بوک بسته شود، تایمر ۳۰ دقیقه‌ای عدم فعالیت فعال شده و کل کانتینر منهدم می‌شود.
3. **علت ارور ۵۳۰ به جای ۵۰۲:** اگر فقط پایتون کرش کند، کلودفلر ارور `502 Bad Gateway` می‌دهد؛ ارور `530 (1033)` نشان‌دهنده قطع کامل ماشین میزبان از شبکه دیتاسنتر کلودفلر بود.

#### راه‌حل:
- متوقف‌سازی تمامی نشست‌های موازی با `colab stop`.
- اجرای دائمی سرویس پایش ضربان قلب (`colab_keepalive.py`) که با ارسال درخواست‌های منظم به اندپوینت داخلی `/health`، از خاموش شدن ماشین جلوگیری می‌کند.

### ۳.۲ محاسبات دقیق حافظه VRAM و کانتکست ۳۲K

مدل `Qwen 3.8 27B Q5_K` با ۱۹.۵ گیگابایت وزن روی کارت L4 با ظرفیت ۲۲.۵ گیگابایت لود می‌شود؛ یعنی فقط **۳.۰ گیگابایت VRAM خالی** برای حافظه KV Cache باقی می‌ماند!

#### فرمول محاسبه حافظه KV Cache:
$$\text{Memory} = 2 \times \text{Layers} \times \text{KV Heads} \times \text{Head Dim} \times \text{Bytes per Element} \times \text{Tokens}$$

برای مدل Qwen 27B:
- تعداد لایه‌ها: $64$
- تعداد هدهای KV: $8$
- بعد هر هد: $128$

```
• حالت FP16 (هر المان 2 بایت):
  1 token = 2 * 64 * 8 * 128 * 2 = 262,144 bytes = 256 KB
  32,768 tokens = 8.38 GB (منجر به OOM و کرش قطعی!)

• حالت پیش‌فرض Q8_0 (هر المان 1 بایت):
  1 token = 128 KB
  32,768 tokens = 4.19 GB (بیش از 3.0 گیگابایت آزاد، کرش یا افت به رم سیستم!)

• راهکار بهینه‌شده Q4_0 (type_k=2, type_v=2):
  1 token = 64 KB
  32,768 tokens = 2.09 GB!
  
  مجموع: 19.5 GB (مدل) + 2.09 GB (کش) = 21.59 GB <= 22.5 GB VRAM!
```

با فعال‌سازی Flash Attention و تنظیم `type_k=2, type_v=2` در `llama-cpp-python`، توانستیم بدون کمترین افت دقت کدنویسی، **پنجره کانتکست کامل ۳۲,۷۶۸ توکنی** را ۱۰۰٪ روی حافظه گرافیک اجرا کنیم.

### ۳.۳ مهندسی رابط کاربری دوطرفه فارسی/انگلیسی (RTL/LTR)

در برنامه‌های وب دوزبانه، استفاده ساده از `<html dir="rtl">` منجر به فجایع ظاهری زیر می‌شود:
1. قرار گرفتن اسکرول‌بار مرورگر در سمت چپ صفحه به جای سمت راست.
2. برعکس شدن پرانتزها، خط تیره‌ها و نقاط در کدهای پایتون و لیست‌های انگلیسی (مانند تبدیل `import asyncio,` به `,import asyncio`).
3. درهم‌ریختگی کدهایی که کاربر پیست می‌کند.
4. پرش و قفل شدن اسکرول صفحه هنگام استریم شدن توکن‌ها.

#### راهکارهای معماری CSS و JS اعمال‌شده:
- **اسکرول‌بار سمت راست:** کانتینر اصلی اسکرول دارای `direction: ltr !important; overflow-y: auto;` است (که باعث می‌شود مرورگر اسکرول‌بار را در سمت راست رسم کند)، و محتوای فرزند آن دارای `direction: rtl !important;` است.
- **ایزولاسیون متن و علائم:** تعریف قانون CSS:
  ```css
  .markdown-body p, .markdown-body li {
      direction: auto;
      text-align: start;
      unicode-bidi: plaintext;
  }
  ```
- **تشخیص هوشمند کدهای ورودی کاربر:** تابع `formatUserText` خطوط حاوی کلیدواژه‌های برنامه‌نویسی (`def`, `import`, `class`, `if`) را استخراج کرده و آن‌ها را داخل بلاک مونو با `dir="ltr"` محصور می‌کند تا سینتکس کد دچار معکوس‌سازی نشود.
- **جلوگیری از قطع اسکرول کاربر:** با استفاده از متغیر `userScrolledUp`، در صورتی که کاربر به سمت بالا اسکرول کند تا کدهای قبلی را بخواند، استریم زنده موقعیت دید او را تغییر نمی‌دهد.

### ۳.۴ تفکیک استدلال و تفکر عمیق (`<think>`)

مدل‌های زبانی در مسائل پیچیده برنامه‌نویسی به صورت طبیعی تمایل به بیان فرآیند استدلال به زبان انگلیسی دارند. اگر این فرآیند مهار نشود، خروجی چت پر از مونوگ‌های متنی پیش از ارائه کد می‌شود.

#### ساختار کنترل دوسطحی:
1. **پرامپت سیستمی:** اجبار صریح مدل به استفاده از ساختار:
   ```
   <think>
   [Internal architectural reasoning and bug analysis]
   </think>
   [پاسخ روان به زبان فارسی و کدهای کامل پایتون]
   ```
2. **فیلتر کلاینت (Regex Monologue Sequestering):** هرگونه استدلال انگلیسی بدون تگ که با کلماتی مانند `We need`, `Let's analyze`, `Thinking Process` شروع شود به طور خودکار استخراج شده و به باکس تاشوی تفکر عمیق هدایت می‌شود.

### ۳.۵ حل بافرینگ استریم کلودفلر (SSE Unbuffered Streaming)

یکی از مشکلات متداول کار با Cloudflare Tunnel، بافر شدن چانک‌های استریم پاسخ تا زمان پایان تولید بود.

#### رفع مشکل:
- کتابخانه Starlette به صورت خودکار مقدار `; charset=utf-8` را به هدر اضافه می‌کرد که باعث می‌شد لبه CDN کلودفلر استریم را بافر کند. با بازنویسی کلاس `EventStreamingResponse` و تثبیت هدر به صورت دقیق:
  ```http
  Content-Type: text/event-stream
  Cache-Control: no-cache
  X-Accel-Buffering: no
  ```
- تزریق یک پدینگ اولیه ۴۰۹۶ بایتی در ابتدای هندشیک استریم (`: <4096 spaces>\n\n`) باعث شد تمامی بافرهای میانی مسیر فوراً تخلیه شوند و تاخیر اولین توکن به زیر **۰.۳ ثانیه** کاهش یابد.

## ۵. اتصال به ابزارهای کدنویسی خارجی (OpenAI API)

سرور پیاده‌سازی‌شده کاملاً با پروتکل استاندارد OpenAI Chat Completions سازگار است. می‌توانید از آدرس تانل در افزونه‌های **Cursor**, **Cline**, **Continue.dev**, **Roo Code** و کتابخانه رسمی پایتون استفاده کنید:

```python
from openai import OpenAI

client = OpenAI(
    base_url="https://xxxx-xxxx.trycloudflare.com/v1",
    api_key="sk-no-key-required"
)

response = client.chat.completions.create(
    model="qwen-27b",
    messages=[
        {"role": "user", "content": "یک اسکریپت چندنخی پایتون برای پردازش لاگ‌ها بنویس."}
    ],
    temperature=0.2,
    max_tokens=4096
)

print(response.choices[0].message.content)
```
